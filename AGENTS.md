# AGENTS.md

## About this repository

This repository is used by Arun Yadav, an AI systems builder, to learn the concepts, workflow, and industry practices behind each project.

## How Arun learns

1. Before building a project, Arun reads its topic notes in the project folder. The README links to each notes file.
2. Then he asks you to build the project step by step, in phases, applying what he learned do not build the whole project in one go instead build with him one step at a time one phase at a time.

## Before planning a project

When Arun asks you to implement a project:

1. Read the project brief in root `projects.md`.
2. Read root `syllabus.md`.
3. Read the relevant project's topic notes, linked from the root `README.md`.
4. Create a phase-by-phase plan for that project before implementation.

## How to write a project plan

- Write the plan in `plan.md` inside the project's folder.
- Start with the project goal, scope, and the main behavior the app will provide.
- Show the target file structure and explain the job of every planned file and folder.
- Order the work from understanding the requirements and setting up the structure through building, reviewing, and testing the app.
- Break work into small numbered steps. For every step, state what we will learn or build, which files it touches, and a clear checkpoint for knowing it is complete.
- Use concise bullets, concrete examples, and plain explanations. Avoid long theoretical paragraphs and unexplained architecture.
- Make the plan practical to follow together: complete one step at a time, explain it before implementation, and pause at each checkpoint before moving on.
- Keep the project's scope focused. Name later-project features that are deliberately out of scope rather than adding them to the build.

## How to teach and build

- Build the project one phase at a time with arun so Arun can understand each part.
- Focus on architecture and the reasons behind it, not line-by-line code.
- Explain why an approach fits, its advantages and disadvantages, and what other approaches are available.
- Help Arun think through design choices. Ask questions that build his reasoning instead of giving him coding quizzes.
- Be comprehensive and clear.

## GitHub workflow

- Do not push an unfinished project while any phase in its agreed plan remains.
- After all phases are complete, review the project changes, stage only the files for that project, commit the finished work, commit locally and ask arun to use `git push`.
